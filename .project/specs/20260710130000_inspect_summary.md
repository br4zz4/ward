# inspect: summary footer

> TLDR: Add a summary footer to `ward inspect` showing counts per error type, similar to test suite output.

**Status:** proposed
**Created:** 2026-07-10
**Owner:** @oporpino

---

## Context

`ward inspect` currently either prints a single error and exits, or prints "no conflicts found".
When there are multiple conflicts or collisions, the output stops at the first error found.
There's no summary of how many issues were found or of what type — making it hard to assess the overall health of the vault at a glance.

## Objectives

- Show a summary footer after the inspect output, like test runners do
- The summary counts each error type separately:
  - Type-1 conflicts (same key defined in multiple files)
  - Type-2 env var collisions (distinct paths collapsing to same env var name)
- Clean run shows a clean summary line (e.g. `✓ 0 conflicts, 0 env collisions`)
- Error run shows counts in red per type and exits non-zero

## Changes

- `internal/cmd/inspect.go`: change `reportInspectError` to collect all issues first, then render per-type detail blocks, then a summary footer with counts per type
- `internal/ward/engine.go` (`InspectScoped`): currently short-circuits on the first error type found — needs to return both a `ConflictError` and an `EnvConflictError` if both exist, so the summary can show totals for each
- `internal/cmd/inspect.go`: update the clean-path output to also use the summary line format

## How to verify

- Run `ward inspect` with no issues → footer shows `✓ 0 conflicts, 0 env collisions`
- Run with Type-1 only → footer shows `✗ 1 conflict, 0 env collisions`
- Run with Type-2 only → footer shows `✗ 0 conflicts, 1 env collision`
- Run with both → footer shows both counts
