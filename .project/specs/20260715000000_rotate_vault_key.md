# Vault Key Rotation

> TLDR: Add `ward rotate-key` command that re-encrypts all vault files with a new age key atomically, rolling back automatically if anything fails.

**Status:** completed
**Created:** 2026-07-15
**Owner:** @oporpino

---

## Context

Once a vault is initialised, the age key never changes. If the key is compromised or needs to be rotated for compliance reasons, there is no safe way to do it today. The user must manually re-initialise the vault and migrate secrets, which is error-prone and risky.

## Objectives

- Allow the user to rotate the encryption key of a ward project in a single command.
- Guarantee atomicity: if anything fails mid-rotation, all files remain in their original state and the original key is restored.
- Never write decrypted data to disk during the process.

## Algorithm

```
1. Discover all *.ward files via secrets.Discover()
2. Generate new key at a temp path (os.CreateTemp)
3. For each .ward file:
   a. Decrypt with old key (in memory only)
   b. Encrypt with new key → write to <file>.ward.new (0644)
   If any step fails → goto ROLLBACK
4. SUCCESS path:
   a. Copy old key → .ward/.key.bkp-<timestamp>
   b. Replace old key with new key (os.Rename)
   c. For each .ward file: os.Rename(<file>.ward.new → <file>.ward)
   d. Delete temp key file
5. ROLLBACK path:
   a. Delete all <file>.ward.new files
   b. Delete temp key file
   c. Print error and exit 1
```

Key points:
- Decrypted bytes exist only in memory, never written to disk.
- `.ward.new` files are the staging area; originals are untouched until all succeed.
- Old key backup (`.ward/.key.bkp-<timestamp>`) is written only after all `.ward.new` files are ready — it is the commit point.
- `os.Rename` is atomic on the same filesystem, so the final swap is safe.
- `.ward/.key.bkp-<timestamp>` is intentionally kept so the user can recover if something goes wrong after the commit point.

## How to verify

```bash
ward init
ward set app.db_password mysecret
ward rotate-key
ward get app.db_password  # must still return "mysecret"
ls .ward/.key.bkp-*       # must exist with old key content
```

Also verify rollback: inject a failure (mock encrypt failure on file N) and confirm:
- No `.ward.new` files remain
- `.ward/.key.bkp-*` was NOT created (failure before commit point)
- Old files decrypt correctly with original key
