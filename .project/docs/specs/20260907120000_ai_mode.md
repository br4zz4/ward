# Modo IA — supressão de valores sensíveis para agentes

> **TLDR**: `--ai-mode` flag + `WARD_AI_MODE` env var + MCP auto-supressão garantem que agentes de IA nunca vejam valores de secrets no contexto — só paths, metadados e instruções de acesso via bash.

## Contexto

Agentes de IA (Claude Code, OpenCode, Cursor, etc.) interagem com `ward` de duas formas: via **MCP tools** (`ward_get`, `ward_tree`, etc.) ou via **bash** (`ward get`, `ward tree`, etc.). Em ambos os casos, os valores dos secrets aparecem no contexto da IA, que pode inadvertidamente armazená-los, resumi-los ou ecoá-los.

O `ward` precisa de um mecanismo universal que:
- Permita à IA **descobrir que um secret existe** (paths, estrutura, descrições)
- **Nunca exponha o valor** no contexto da IA
- Force o acesso ao valor via bash, onde o agente pode pipear/redirecionar sem ler

## Objetivos

1. **Flag `--ai-mode`**: suprime valores em `ward get`, `ward secrets`, `ward tree`, `ward file extract`
2. **Env var `WARD_AI_MODE`**: atalho para agentes que suportam injeção de env vars (OpenCode, Claude Code)
3. **MCP auto-supressão**: todas as tools MCP de leitura (`ward_get`, `ward_tree`, `ward_envs`, `ward_file_extract`) suprimem valores automaticamente, sem flag
4. **Mensagens de onboarding**: `ward install` e `ward init` instruem o usuário a configurar `WARD_AI_MODE=1` no agente
5. **MCP `ward_get` reformulado**: retorna JSON estruturado com instrução de bash, nunca o valor

## Fora de escopo

- `ward catalog` (Fase 2) — comando novo com metadados
- `_meta` no `.ward` (Fase 2) — descrições inline
- Bloqueio de comandos de vazamento no `ward exec` (Fase 3)
- `ward raw` — não entra no escopo de supressão (o usuário não o listou)

## Mudanças

### 1. Detecção de modo IA (`internal/cmd/helpers.go` ou novo arquivo)

Nova função `isAIMode()`:

```go
func isAIMode() bool {
    // MCP mode is always AI mode
    // WARD_AI_MODE env var
    // --ai-mode flag
}
```

Resolução: `WARD_AI_MODE=1` env var → flag `--ai-mode` → MCP built-in.

### 2. Flag global `--ai-mode` (`cmd/ward/main.go`)

Persistent flag registrada no root command. Armazenada em variável de pacote `cmd`.

### 3. `ward get` (`internal/cmd/get.go`)

Em modo IA:
- **Recusa executar** com mensagem: "AI mode active — secrets are never exposed in context. Run without `--ai-mode` in a shell to access the value."
- Não imprime valor, não imprime tree, não gera OTP.

### 4. `ward tree` (`internal/cmd/tree.go`)

Em modo IA:
- Mesma estrutura da árvore, mas **valores substituídos por `<sensitive>`**
- Origins mantidos (arquivo:linha)
- Legendas mantidas

### 5. `ward secrets` (`internal/cmd/secrets.go`)

Em modo IA:
- Mesma tabela de env vars, mas **valores substituídos por `<sensitive>`**
- Origins mantidos
- OTP: também `<sensitive>`

### 6. `ward file extract` (`internal/cmd/file.go`)

Em modo IA:
- **Recusa executar** com a mesma mensagem do `get`

### 7. MCP server (`internal/mcp/server.go`)

Todas as tools de leitura passam `--ai-mode` internamente:

| Tool | Mudança |
|---|---|
| `ward_get` | Passa `--ai-mode`; resposta reformulada como JSON instrucional |
| `ward_tree` | Passa `--ai-mode`; resposta é tree sem valores |
| `ward_envs` | Passa `--ai-mode`; resposta é `KEY=<sensitive>` |
| `ward_file_extract` | Passa `--ai-mode`; resposta é instrução de bash |
| `ward_exec` | **Sem** `--ai-mode`; executado normalmente |
| Demais tools | **Sem** `--ai-mode`; comportamento inalterado |

**Formato do `ward_get` no MCP**:

```json
{
  "path": "shared.db.password",
  "sensitive": true,
  "description": "No description available",
  "instructions": "Run in a shell: ward get shared.db.password",
  "hint": "Ward secrets are never exposed in AI context. Use bash to access values directly."
}
```

### 8. `ward install` (`internal/cmd/install.go`)

Adiciona banner informativo após instalação:

```
🔐 Ward detected. To protect secrets from AI agents:

   1. Set WARD_AI_MODE=1 in your agent config

   2. For OpenCode, add to opencode.json:
      "env": { "WARD_AI_MODE": "1" }

   3. For Claude Code, add to CLAUDE.md:
      env: WARD_AI_MODE: "1"

   Without this, AI agents will see secret values in plain text.
```

### 9. `ward init` (`internal/cmd/init.go`)

Mesmo banner informativo adicionado ao final do output de `ward init`.

### 10. `ward_docs` no MCP

Atualizar `wardDocs` para documentar o comportamento de AI mode e instruções de configuração.

## Como verificar

1. **Flag `--ai-mode` no CLI**:
   ```bash
   ward get db.password --ai-mode     # recusa
   ward tree --ai-mode                # paths sem valores
   ward secrets --ai-mode             # KEY=<sensitive>
   ward file extract sa.json --ai-mode # recusa
   ```

2. **Env var `WARD_AI_MODE`**:
   ```bash
   WARD_AI_MODE=1 ward get db.password  # recusa
   WARD_AI_MODE=1 ward tree             # paths sem valores
   ```

3. **Sem modo IA, comportamento normal**:
   ```bash
   ward get db.password              # retorna valor normalmente
   ward tree                         # árvore com valores
   ```

4. **MCP**: iniciar `ward --mcp` e chamar `ward_get` → retorna JSON instrucional, nunca o valor

5. **`ward install` e `ward init`**: output inclui banner de AI mode
